# walkthrough-assist

## 目的と責務

指定されたコードまたはテストをHumanが理解し、その妥当性を判断できるよう対話する。基礎説明は `../explain-code/SKILL.md`、テストの静的報告は `../test-report/SKILL.md` を正本とする。
本Skillは説明順・掘り下げ・対話中の発見事項の統合を担当する。基礎Skillの分析を毎回やり直さず、問題発見のための網羅的な自律レビューへ広げない。
source / test / config を変更せず、テスト・対象コードを実行しない。実行と修復はHumanが明示起動する `test-verify` の責務であり、対話から自動遷移しない。

## 対象と基礎成果

依頼、repository / ref、指定範囲、要求、コード・テスト、既存説明・報告と指摘を受け取る。Humanの対象指定を優先し、曖昧さが説明を変えるときだけコード／テストや範囲を局所確認する。
対象の基礎Skillが扱った範囲を対話の基準とし、関連根拠の調査はその理解・判断に必要な範囲へ限定する。対象外の気づきは境界を明示して保持し、調査範囲を自動拡張しない。

既存成果の対象、revision、要求根拠と参照コード・テストを現状と照合する。同じ対象で現状に適合する部分は再利用し、変更・欠落の影響を受けた意味領域だけ更新する。時刻やファイル名だけで新旧・適合を判断しない。
適切な成果がない場合は、コードなら `explain-code`、テストなら `test-report` をそのSkillの指示に従って先行実行する。部分成果がある場合も不足・古い部分に必要な基礎Skillを利用し、更新対象外の根拠・指摘を保つ。
本Skillの明示起動はこの範囲の基礎Skill利用を含む。これは基礎説明・静的報告の作成であり、テスト実行や修復の許可ではない。取得できない根拠は未確認のまま残し、全体を確認済みにしない。成果の保存・更新は明示された destination / write authority に従い、既定では会話内に返す。

## 理解と対話

開始時に `../../references/model-construction.md`、`../../references/agentic-model-construction.md`、`../../references/interactive-model-construction.md` を読む。
一回のtop-level invocationで本Skillが一つのtask-local Local Modelを所有する。基礎成果を根拠付きで取り込み、調査とHumanの発言を同じ理解へ統合する。Humanの事実・文脈、判断、質問を区別し、技術的な未確認事項を承認で確定しない。
調査はAgentic、Humanとの意味の共同構築は本Skillが選んだ範囲でInteractiveを利用する。Methodの切り替えと対話全体の終了は本Skillが扱い、Humanが終了したときは未解決のまま返せる。

目的・役割・データや状態のつながりからコアとなる振る舞い・処理を特定する。コアは複数でもよい。同じ目的の細かな手段を不必要に分割せず、コード量・複雑さ・テスト件数を重要度に置き換えない。
最初に全体と説明候補を短く示し、Humanの指定があればそこから、なければ重要なまとまりから一つずつ説明する。各まとまりで意味と根拠、妥当性を判断するための条件・不明点を示してHumanの応答を待つ。全項目を自律的に消化しない。

Humanは対象・範囲・分類を変更し、質問、`next`／次、`skip`、終了を選べる。質問・訂正が続く間は現在の対象に留まり、必要な根拠だけ掘り下げる。`next`では次の未説明のまとまりへ進み、`skip`ではそのまとまりを未確認として残して次へ進む。最後の項目の後は終了まとめを返す。
説明済み、スキップ、Humanが明示的に妥当と判断した範囲、未解決・未確認を区別する。説明を聞いたことや次へ進んだことを承認にしない。明示的な判断もその対象・条件に限定し、全体の承認や実装権限へ広げない。

### テストの対話

`test-report` の対象内で、本質的な判断・計算・状態変更ごとに関連テストをグループ化する。コアの検証から説明し、周辺的・単純な確認も候補として残す。分類は説明順と深さのために使い、品質の合否には使わない。
各グループで、何を保証するか、どの条件・期待結果をどのassertionやデータで検証するかを要求と対応づける。質問に応じて個別テストや実装へ進む。
期待値の根拠は要求された振る舞いに置く。実装変更の結果そのものを正解にせず、要求・実装・テストの期待を区別する。説明中に不足・期待値や検証の不備・不要や重複の疑いを発見したら、根拠と見逃しうる影響を確認して指摘する。静的な疑いと実行で確認した事実を混同しない。

### コードの対話

`explain-code` の全体説明 → 実行経路 → 各詳細説明を起点とする。全体の目的とコア処理間の関係を示し、実際の呼び出し・順序を辿れる経路を示してから意味単位の詳細へ進む。
単位は機能・主要フロー・責務の意味から決める。一つの関数内の異なる意味を分け、複数関数にまたがる一つの役割をまとめられる。関数・クラス一覧をそのまま対話単位にしない。
Humanの疑問に応じて関数・クラス・分岐・副作用へ掘り下げ、目的達成、責務分担、処理間のデータ・状態・失敗時の整合性を全体フローと照合する。未知の接続や原子性は未確認として残す。
不足・重複・依存関係などの問題を指摘するときは実害と根拠を確認する。責務が混在しているだけで機械的な分割を推奨しない。

## 発見事項の保持と終了

既存指摘、説明中の新発見、Humanの指摘を根拠・対象・確認状態とともに保持する。同じ問題は既存IDや出典との対応を保って統合し、異なる条件の指摘を潰さない。矛盾は要求・適用条件・現状の根拠を照合し、解消できなければ両方の主張と未確定理由を残す。
Humanの訂正で理解が変われば影響部分を更新し、無効になった解釈は根拠付きで置換する。新発見を既存成果にないという理由で捨てず、単なる候補を確認済みの不具合にしない。

Humanが終了したら追加調査や残項目の説明を始めず、到達した理解、修正点・推奨点、未確定事項、未説明・skipした範囲を簡潔に返す。テストでは `test-report` の既存指摘へ対話の追加指摘を統合して示す。途中終了でも発見事項を失わない。
全項目の説明完了や指摘なしを品質合格にせず、Humanの判断済み範囲と観測限界を示す。次の作業は候補として提示し、自動実装・テスト修正・検証開始は行わない。
出力前に `../../references/human-facing-projection.md` を適用し、根拠、未確認範囲、Human判断の対象と条件が保持されていることを確認する。
