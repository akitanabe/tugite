# explain-this

## 目的と境界

実装を書いていないHumanが、対象の処理がどう進み、各関数やクラスがその流れの中で何を担い、次へどうつなぐかを理解できるようにする。
コードは、その流れを確かめる根拠と、実装を辿る目印として使う。
既存実装と実装後の変更を扱い、品質判定・改善計画・自動修復へは広げない。

## 内部での理解の構築

開始時に `../../references/model-construction.md` と `../../references/agentic-model-construction.md` を読む。
explain-thisが一回のtop-level invocationで一つのtask-local Local Modelを所有し、Agentic Model Constructionで問いに必要な理解を構築する。
これらのMethodが返す理解・根拠・留保は内部の判断材料であり、Human向けに列挙する出力項目ではない。

コードを主な根拠に、呼出しだけでなくMiddleware・設定・登録による接続、実行順序、データ受渡し、判断、状態取得・変更を調べる。
挙動の理解に必要なら共通基盤やトランザクション・失敗時の扱いまで追う。調査の深さを出力の量に直結させず、調べた内容を依頼範囲の主要な役割と遷移へ要約する。
新しい根拠は同じLocal Modelへ反映し、矛盾した理解を残さない。説明の意味を変えるHuman固有の意図や対象が不可欠なら、Methodの外で必要な点だけ確認する。
実装の事実、実行観測、解釈、意図、テスト期待値を混同しない。意図不明や未確認事項は、それが説明の理解を左右する箇所に限って短く示す。

## 小さな確認と終了

テストは補助根拠であり、なくてもコードから分かる流れを説明する。実行が重要な不明点を解消し得る場合だけ、問いと入力・環境を絞って小さく確認する。
実行前に `../../references/external-effects.md` を適用し、既存authorityの内側で行う。説明のためにsource / test / configや恒久環境を無断変更しない。
確認不能なら、説明できる流れと重要な未確認箇所を簡潔に返し、全体確認済みとは扱わない。確認しにくさだけで設計不良と断定しない。

## 最終応答の組み立て

参照文書を読んで調査を終えたら、この節へ戻り、依頼された処理の概要フローを組み立てる。
Humanが指定した開始点から終点まで、指定がなければ対象の入口から結果までの主要な節点を選ぶ。初期化や依存生成は、その経路を理解するのに欠かせない場合か、それ自体が対象の場合だけ選ぶ。

選んだ主要節点ごとに、実在する関数・クラス・構造体などの識別子を先に置いた短い寄与文を一つ書き、実際の処理順につなぐ。
その文は「この要素が流れの中で何を担い、次へ何を渡すか」を表す。識別子の実際の責務を述べ、そのスコープ内から呼ぶ別要素の仕事を当該要素の責務へ混ぜない。
独立した次の主要節点は別の行へ分け、従属する補助処理は主要節点の働きへまとめる。共通基盤自体が対象でも、この役割の粒度を使う。
接続の成立や確定順序を理解するのに不可欠な境界、実装未提供や未確認の橋渡しだけを短い注記にする。推測でつながない。

以下は架空の画像受付による粒度の例であり、実対象の名称や必須書式ではない。

```text
UploadController.receive：画像を受け付け、保存処理へ渡す
→ AssetStore.save：画像を保存し、画像IDを返す
→ IndexQueue.enqueue：画像IDを索引作成ジョブへ渡す
```

候補を書いたら各文を見直す。役割や受渡しではなく、コード内部の動作を解説している文は削り、寄与文に詰め込んだ内部手順も落とす。
正確な値・フィールド・確認項目・失敗の分類・状態保存や復元の仕組みは、それ自体を明示的に問われた場合だけ説明する。詳細を削っても、実際の接続・責務・不可欠な順序と未確認箇所は保つ。
根拠への参照は簡潔に添える。コード抜粋は求められた場合か、接続を示すために不可欠な箇所に限り、原文・出典・省略箇所を保つ。別々の断片を実在の一関数として合成しない。

この削り込みを済ませた候補だけへ `../../references/human-facing-projection.md` を適用する。調査結果や未選択の詳細は渡さない。
返された文も同じ役割の粒度と責務の対応で確認し、説明の追加や内部手順への展開は採用しない。内容の選び直しが必要ならこの節で候補を直し、変更した文章へ同じMethodを再適用する。
応答はこの概要フローから直接始め、全体を追えたところで終える。導入・詳細節・役割一覧・調査報告を付け足さず、固定の見出し・矢印形式・項目数は要求しない。
説明の保存は明示されたdestination / write authorityに従う。
