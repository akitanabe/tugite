# clarify-it — Philosophy

`clarify-it` がなぜこの構造を採用するのか、その長期的な設計意図を示す。

本書は非規範であり、新しい obligation を作らない。`SKILL.md` の Specification / Method / Casebook が優先する。
通常実行には必須ではなく、`SKILL.md` 内の recovery data だけでも skill は動作できる。本書は、Specification / Method / Casebook の矛盾、解釈衝突、
想定外ケースで設計意図を深く確認するための local reference である。本書でいう「成果物へ反映」は、成果物を直接編集する
ことではなく、現在の意思決定モデルを caller / Human へ返すことを指す。

## 1. 中核命題

> **clarify-it は、Human の判断権限を維持したまま、意思決定モデルの構築・圧縮・整合性維持を Agent に委ねる協働型の意思決定手法である。**

Human は、目的、価値、許容範囲、責任境界など、Human にしか決められない事項を判断する。
Agent は、調査、分析、導出、論点整理、依存関係の維持、矛盾の検知、再圧縮、最終的な再統合を担う。

`clarify-it` の目的は、Human への質問回数を単純に減らすことではない。

> **Human の有限な認知資源を、本当に Human が決める必要のある価値判断へ集中させ、その判断品質を守ること。**

そのために Agent は判断空間を縮小するが、Human の判断権限まで縮小しない。

## 2. 設計前提

### 2.1 Human の認知資源は有限である

Human が、長い対話の全期間にわたって過去の判断、判断時の前提、論点間の依存関係、例外、未決事項、論理的不整合を同時に
保持し続けることを前提にしない。これは Human の欠点として矯正すべきものではなく、Human と Agent の特性差として設計に
取り込むべき前提である。

### 2.2 Agent は継続性を持つが、万能ではない

Agent は Human より広い対話状態を保持し、導出や整合性確認を継続的に行える。一方で、Agent がすべての事実を知っているとは
限らず、通常の調査で解消できない不確実性も存在する。`clarify-it` は Agent に万能性を要求しない。Agent に求めるのは、自らの
不確実性を Human の価値判断へすり替えず、分からない範囲を正確に示すことである。

### 2.3 長い対話は質問列ではなく、更新されるモデルである

Human の回答は、あらかじめ用意された質問列を一つずつ消化するための入力ではない。一つの判断によって、後続の問いが不要になる、
複数の論点が一つの上位原則へ統合される、既存の選択肢が成立しなくなる、新しい前提や評価軸が現れる、過去の判断を再配置する
必要が生じることがある。`clarify-it` は対話を固定フローではなく、**Human の判断によって更新され続ける意思決定モデル**として扱う。

## 3. 基本原則

### Principle 1 — 責任は、それぞれの特性に沿って分担する

> **Human は価値判断と結果責任を担い、Agent は導出可能な事項と対話過程の整合性に責任を持つ。**

Human が担うのは、Human の意図によって正解が変わる判断である。Agent が担うのは、Human の判断を受け取るまでの準備と、
受け取った後のモデル更新である。

Agent の経過責任とは、内部の思考過程をすべて逐次開示することではない。過去の判断が失われていないこと、前提と結論の関係が
崩れていないこと、導出可能な事項を Human に押し返していないこと、重要な矛盾が隠されていないこと、次の判断が現在のモデルに
基づくこと、最終成果物が採用済み判断を正しく反映することを維持する責任である。

Human は自らの判断を変更でき、判断変更そのものを正当化する責任はない。ただし、その変更によって既存の判断モデルが大きく
巻き戻る場合は、Agent が新しいモデルを再構成できるだけの方針、適用範囲、道筋を示す責任を持つ。

> **Human は変更の理由を証明する必要はないが、どこへ向かう変更なのかは示す。**

### Principle 2 — Human の認知資源は、価値判断へ集中配分する

Human の認知資源は、単に節約すべきコストではない。それは、Human にしかできない判断へ集中配分すべき有限資源である。
したがって `clarify-it` は、質問数、文字数、対話ターン数の最小化を直接の目的にしない。

簡潔な一問で十分な場合は簡潔にする。一方で、大規模な方針変更や前提の再定義では、Human に十分な説明空間を返した方が判断品質は
高くなる。一問一答も目的ではない。重要なのは、Human が一度に複数の独立した判断文脈を保持せず、一つの整合した decision context
に集中できることである。強く結合した複数の回答要素は、分離する方が文脈再構成負荷を増やすなら一緒に扱える。反対に、一つの
context が重すぎるなら複数ターンへ分けられる。形式ではなく、Human の判断品質を基準にする。

### Principle 3 — 判断空間を圧縮するが、判断権限は圧縮しない

> **Agent は Human が判断する範囲を狭めるが、Human に属する判断を奪わない。**

Agent は、Human に問いを提示する前に、調査で解消できる不確実性、技術的に優劣を判断できる選択、既存判断から導出できる事項、
劣後する選択肢、同じ上位原則へ統合できる下位論点を可能な範囲で処理する。その結果として残る、Human の意図・価値・許容範囲に
依存する判断が Human Decision Point である。

Human Decision Point は、問題が重要だから発生するのでも、Agent が難しいと感じたから発生するのでもない。

> **Agent が処理できるものを処理した後にも、Human の価値判断だけが残るために発生する。**

Agent の推奨も Human の決定を代替しない。推奨は判断空間を理解するための支援であり、Human の判断権限を黙って吸収する仕組みではない。

### Principle 4 — Agent が対話の継続性を持ち、意思決定モデルを更新する

Human が過去判断との論理的一貫性を継続的に監視することを前提にしない。Agent は、どの判断がどの context で行われたか、どの
前提に依存しているか、どの範囲へ適用されるか、新しい判断が既存モデルへどう影響するかを追跡する。

過去の Human 判断は、明示された適用範囲では尊重する。しかし、別の論点へ勝手に一般化しない。過去の類似判断は参考情報にはなるが、
Human の固定的な人格や永続的な好みとして現在を拘束しない。Human の判断によって新しい上位概念が現れた場合、Agent は古い質問列を
守るのではなく、下位論点を新しい構造へ再配置する。

結論への Trust は、その結論を支える前提と依存関係に基づく。重要な前提が崩れた場合、その下流の結論を形式上維持し続けてはならない。
局所的な修正で Trust を回復できないなら、まだ信頼できる地点まで戻ってモデルを再構成する。

最終成果物は、対話中の判断を時系列で並べた承認ログではない。

> **対話の成果は、現在の前提のもとで再統合された、一つの意思決定モデルである。**

`clarify-it` は成果物や Issue を編集しないため、ここでいう成果は現在モデルを caller / Human へ返すことを指す。履歴が必要な
場合は、成果物本体とは別に保持できる。

### Principle 5 — Agent は過去の結論ではなく、現在の根拠に忠実である

Agent の推奨は、擁護すべき立場ではない。新しい事実、Human の指摘、反証材料、前提変更によって優劣が変われば、Agent は推奨を変更する。

> **推奨変更は失敗ではない。根拠が変わったのに結論を維持することが失敗である。**

Agent は、推奨を提示する際に、その結論を変えうる主要な反証材料や有力な代替案を合理的な範囲で確認する。ただし、反証探索そのものを
目的化して対話テンポを失ってはならない。完全性ではなく、判断に十分な強度を目指す。

Human に提示する情報は圧縮できる。しかし、圧縮は根拠の消去ではない。

> **圧縮された説明は、必要に応じて正確に展開できなければならない。**

Human が詳細を尋ねた場合、Agent は当初の推奨を構成した前提、事実、比較、判断根拠を正確に説明する。後からもっともらしい理由を生成し、
当初の根拠とすり替えない。

### Principle 6 — 局所的な正しさより、全体としての適切さを優先する

個々の質問が論理的に正しくても、対話全体が適切とは限らない。仕様や設計を細かく詰めていると、各質問には妥当な理由があり、各選択肢にも
意味があるため、主体者である Agent 自身には過剰な詳細化へ気づきにくい。

> **発散は、間違った質問が続くことでだけ起きるのではない。正しい質問が細かすぎることでも起きる。**

Human が、同じような低情報量の承認しか返していない、価値判断をしている感覚がない、どちらでもよい細部が続いている、上位原則から
自動的に決まりそうだと感じる、そもそもここまで決める必要がないと感じる場合、その違和感は対話粒度に対する重要な外部シグナルになる。

Agent は「個々の質問は正しい」と現在の進行を擁護せず、一段上の抽象度へ戻る。そこで複数の論点を一つの上位原則へ統合できないか、
Agent の自律判断へ戻せないか、Specification ではなく Method や内部実装へ入り込んでいないか、例外を追加するより上位概念を更新すべきでは
ないかを再評価する。

局所的な正しさを積み重ねることより、対話全体が本来の目的と適切な粒度を維持していることを優先する。

### Principle 7 — 境界は厳密にし、方法は Agent の自律性に委ねる

`clarify-it` は、Human と Agent の責任境界、Human Decision Point の条件、判断支援の完全性、再構成、完了条件などを厳密に定める。
一方で、それを実現する Agent の内部手順は必要以上に固定しない。判断候補の探索、内部状態、Frame を捉え直す時機、依存関係の表現、
再圧縮アルゴリズムは、Specification を満たす限り Agent に委ねられる。

> **強く固定するべきなのは責任と成果の境界であり、Agent の思考経路ではない。**

Method の過剰な詳細化は、現在の Agent の限界を将来の Agent にまで強制する危険がある。Agent の自律性を維持することで、Agent の性能向上を
`clarify-it` の品質向上へ直接反映できる。Human に判断を求められる事項であっても、それが本当に Human の価値判断なのか、それとも Agent が
自ら決めるべき実行詳細を Human に委ねようとしているだけなのかを区別する。

## 4. `clarify-it` が目的としないもの

`clarify-it` は、次を目的としない。

- Human への質問数を機械的に最小化すること
- 常に一問一答の形式を守ること
- Agent が Human の価値判断まで自動化すること
- Agent がすべての不確実性を解消すること
- Agent の内部思考過程を逐一 Human に開示すること
- 過去の Human 判断を固定的な嗜好モデルとして一般化すること
- 対話中に採用されたすべての判断を最終成果物へ残すこと
- Agent の内部状態や実行アルゴリズムを固定すること
- Human を対話状態の記憶装置や整合性監視者として使うこと

## 5. 文書体系との関係

### Philosophy

`clarify-it` の目的、設計前提、責任分界の理由を示す。非規範的であり、隠れた必須要件を作らない。

### Specification

`clarify-it` への適合性を定める唯一の規範源。MUST と SHOULD により、外部から確認できる責任と振る舞いを定義する。

### Method

Specification を満たすための標準的な実行モデルを示す。Agent の自律性を不必要に拘束しない。

### Casebook

Specification と Method だけでは誤解しやすい境界を、成功例、失敗例、反例によって具体化する。Casebook は規範ではない。新しい規則が
必要になった場合は Specification へ明示的に反映する。

## 6. 要約

`clarify-it` の中心にあるのは、Human の負荷を単純に下げることではない。Human と Agent の異なる特性を前提に、責任を適切に分担することである。

- Human は価値判断と結果責任を持つ
- Agent は導出・圧縮・整合性維持・再統合を担う
- Human の認知資源は、本当に必要な価値判断へ集中させる
- Agent は判断空間を圧縮するが、判断権限は奪わない
- 対話を固定質問列ではなく、更新される意思決定モデルとして扱う
- Agent は過去の結論ではなく、現在の根拠に忠実である
- 局所的な正しさより、全体としての適切さを優先する
- 責任と成果の境界は厳密にし、内部手順は Agent の自律性に委ねる
- 最終成果物には、承認履歴ではなく現在の一貫した意思決定モデルを残す

> **Human は結果に責任を持ち、Agent はその結果へ至る対話の整合性に責任を持つ。**
